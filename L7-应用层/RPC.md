# RPC 远程过程调用

## 概念

RPC (Remote Procedure Call) 远程过程调用，这只是一个统称，重点在于方法调用（不支持对象的概念），具体事项甚至可以用 RMI RestFul 等去实现，但一般不用，因为 RMI 不能跨语言，而 RestFul 效率太低。多用于服务器集群间的通信，因此常使用更加高效短小精悍的传输模式可以提高效率。

从单机到分布式产生了好多分布式通信协议，分布式通信最基本仍然是基于 TCP/IP 协议栈的二进制数据传输。

---

## 最基本的通信模型

```text
Client                                      Server
  |                                           |
  |------------------------------------------>|  二进制用户id
  |                                           |
  |<------------------------------------------|  二进制用户信息
  |                                           |
```

| Client 步骤 | Server 步骤 |
|-------------|-------------|
| 1. 连接Server | 1. 接收socket |
| 2. 将ID读入Byte Slice | 2. 读出二进制ID |
| 3. 转换成二进制发给服务端 | 3. 转换为Int |
| 4. 阻塞等待读入，服务器写入 | 4. 获取用户对象 |
| 5. 先读取int给id，再读取string给name，再new成新对象来用 | 5. 将用户对象的id/name按二进制顺序写回，先写缓存再刷 |

非常不灵活，比如对象添加属性。
