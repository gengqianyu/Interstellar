# WireGuard 架构与数据包流转全流程解析

本文详细解析 WireGuard（包含内核态与 `wireguard-go` 用户态实现）在启动、路由注入以及数据包处理过程中的底层机制，帮助理解隧道通信的完整生命周期。

---

## 一、 启动与初始化阶段

当 WireGuard 启动并加载配置文件时，会在操作系统中建立必要的虚拟接口与路由映射，包含以下 4 个核心步骤：

```
[解析配置文件] ──> [创建 TUN 虚拟网卡] ──> [在物理网卡绑定 UDP 51820 监听] ──> [配置操作系统路由表]
```

1. **创建虚拟网卡（TUN 设备）**  
   在内核中创建并注册一个三层（L3）虚拟网络接口（Linux 下通常为 `wg0`，macOS 用户态实现下通常为 `utunX`）。
2. **绑定 UDP 监听端口**  
   在**物理网卡**（真实网络栈）上开启并绑定一个 UDP Socket（默认端口 `51820`），用于后续收发加密的隧道数据包。
3. **初始化 Cryptokey 映射表**  
   在内存中构建一张“公钥 ↔ AllowedIPs ↔ Endpoint”的映射表（即 WireGuard 内部路由表）。
4. **注入系统路由表（关键步骤）**  
   * 告知操作系统的网络栈：“凡是目的 IP 匹配 `AllowedIPs`（例如 `1.2.3.4` 或全局 `0.0.0.0/0`）的数据包，统统交给 `wg0` / `utunX` 接口处理！”
   * 若使用 `wg-quick`，它还会利用路由策略（Policy Routing）或防火墙标记（Fwmark）来防止路由环路。

---

## 二、 数据包发送全流程（Outbound Lifecycle）

假设场景如下：
* **本机（Client）**：已启动 WireGuard，物理网卡为 `eth0`/`en0`，UDP 监听端口为 `51820`。
* **目标应用（App）**：发起请求访问 IP `1.2.3.4`（该 IP 包含在 WireGuard 的 `AllowedIPs` 中）。

### 1. 从内核协议栈到 TUN 设备

```
+-------------------------------------------------------------------------------+
| 1. App (Socket) -> 2. 四层 TCP/UDP 构建 -> 3. 三层 IP 路由查找 (决定走 wg0/utun)    |
+-------------------------------------------------------------------------------+
                                       │
                                       ▼
                         +---------------------------+
                         | 4. 驱动程序将包写入 TUN 设备 |
                         +---------------------------+
```

1. **App 产生数据**：App 调用系统 Socket API（如 `sendto` / `connect`），发起针对 `1.2.3.4:443` 的请求。
2. **构建原始 IP 包**：内核网络栈为其封装 **TCP/UDP 报头** 和 **明文 IP 报头**（源 IP: `10.0.0.2`，目的 IP: `1.2.3.4`）。
3. **三层路由查找（Routing Lookup）**：
   * 内核网络栈查阅**系统主路由表**：“目的地址 `1.2.3.4` 应该从哪个网卡发出？”
   * 路由表匹配成功，出口网卡为 **`wg0`（或 `utunX`）**。
4. **递交给 TUN 设备**：内核将该**未加密的原始 IP 数据包**推送到 `wg0` 网卡的发送队列中。

---

### 2. 从 TUN 设备到物理网卡（UDP 51820）

数据包到达 TUN 设备后，WireGuard 执行加密与二次封装：

```
  [明文 IP 包] ──>  TUN 虚拟网卡 
                         │
                         ▼
             WireGuard 协议栈 (内核模块 / wireguard-go)
                         │ 1. 查找 AllowedIPs 匹配 Peer 公钥
                         │ 2. ChaCha20-Poly1305 加密载荷
                         │ 3. 加上 WireGuard 报头与外层 UDP/IP Header
                         ▼
               物理 Socket (UDP :51820)
                         │
                         ▼
             操作系统物理网络栈 (IP 路由查找 -> 真实网卡 eth0/en0)
                         │
                         ▼
                     [公网传输]
```

1. **WireGuard 截获数据包**：
   * **内核态 WireGuard**：作为网卡驱动直接在内核注册回调函数，提取发往 `wg0` 的 IP 包。
   * **用户态 `wireguard-go`**：通过读取 `/dev/net/tun` 或 `/dev/utunX` 的字符设备文件描述符（FD），将明文 IP 包从内核空间**读取到用户空间**。
2. **Cryptokey 密钥路由查找**：
   * WireGuard 检查明文 IP 包的目的地址 `1.2.3.4`。
   * 查询内部映射表，找到能够处理 `1.2.3.4` 的 Peer **公钥**及该 Peer 的**公网 Endpoint（如 `203.0.113.5:51820`）**。
3. **对称加密与封装（Encapsulation）**：
   * 使用与该 Peer 协商好的共享对称密钥（基于 Noise 协议与 Curve25519）对原始 IP 包进行 **ChaCha20-Poly1305 加密**。
   * 在加密载荷外层加上 WireGuard 报头（包含 Type、Index、Nonce 等）。
4. **构造外层 UDP 数据包**：
   * 构造全新的外层 IP/UDP 数据包：
     * **外层源 IP:端口**：`物理网卡 IP : 51820`
     * **外层目的 IP:端口**：`203.0.113.5 : 51820`（Peer 的 Endpoint）
5. **从物理 Socket 发送（二次进入系统网络栈）**：
   * WireGuard 将封装好的外层 UDP 数据包调用物理 Socket 发送。
   * 操作系统网络栈再次进行路由查找，这次匹配到物理网卡（如 `eth0`），通过物理链路发送至公网。

## 三、 数据包封装对比（“套娃”结构）

WireGuard 的本质是通过二次封装实现隧道传输：

```
【App 原始数据包（明文）】
+------------------------------------------+
| 原始 IP 头 (10.0.0.2 -> 1.2.3.4) | 原始 Payload |
+------------------------------------------+

                     │ (经过 WireGuard 加密与二次封装)
                     ▼

【公网传输的数据包（外层封装）】
+-------------------------------+-----------------------------------+
| 外层 IP 头 (公网 IP -> Endpoint) | WireGuard | 加密后的原始 IP 包      |
| 外层 UDP 头 (51820 -> 51820)    | Header    | (包含 10.0.0.2 -> 1.2.3.4)|
+-------------------------------+-----------------------------------+
```

## 四、 防范路由环路机制（Routing Loop Prevention）

当 `AllowedIPs = 0.0.0.0/0`（全局代理）时，WireGuard 需确保发出的外层 UDP 包（目的地为 `Endpoint IP`）不会被误路由回 `wg0` 网卡，造成死循环。不同平台/实现的处理机制如下：

* **Linux (内核态)**  
  WireGuard 会给外层 UDP Socket 打上特定的**防火墙标记（Fwmark，如 `0xca6c`）**。系统的策略路由（Policy Routing）规则规定：*带此 mark 的包强制绕过 wg0 路由，走物理网卡的默认网关*。
* **macOS / Userspace (`wireguard-go`)**  
  在创建物理 UDP Socket 时，调用底层的接口绑定 API（如 `SO_RESTRICT_TO_IFNET` 或 `IP_BOUND_IF`），显式将该 Socket 锁定在具体的物理网络接口上，从而绕过全局路由拦截。
